This game was created for my GAM420: Creative Computation class. It was the first time I ever coded a game in its entirety, and I’m quite happy with what I learned and how I applied it. I had about a month to work on it.

## Objective

The objective of this project was to create a short playable experience designed around a single mechanic. The mechanic should be engaging when repeated several times. In addition, the mechanic must change or have variation without adding new mechanics.

## Design

From the beginning, I wanted this experience to facilitate contemplation and reflection. I wanted to stay away from minigame or arcade game style mechanics, which are often face paced and encourage competition. At the time this project was assigned, I had been thinking about the poem “The Road Not Taken.” by Robert Frost, which ended up forming the basis of the central theme of the game.

From there, I decided on the gameplay loop: the player would come across branching paths in the woods and choose one. Eventually they would come across another set of paths and have to choose again. The player would not be able to go back and change paths.

But how to make those choices meaningful? After talking about it with my professor, we decided that the easiest way to implement some sort of significance to each path was to change the ambient sound according to which one the player chose. Things like a flowing river or birdsong. I like this idea because it invites the player to pay attention to their environment using a sense other than vision. Additionally, I deliberately left the signposts the player encounters blank in order to emphasize the discovery aspect of choosing a path.


## How It Works

There are two types of chunks; “main” and “branch” chunks, which are used to create the illusion of an infinite path. Chunks in this case are square slices of an environment. The main chunk has a single path running through the middle. Branch chunks continue straight for a little bit before splitting into two paths at a signpost. There are several branch chunks in the game. Each path coming out of a branch chunk is assigned its own unique sound clip. When a player goes down a path, it tells an audio source to play the clip assigned to that path.

I wanted to make movement as simple as possible, and I also wanted to restrict movement to certain directions since I didn’t want them to go backwards. Essentially, the player is “on rails” and can only move forward. The movement is modeled after infinite runners where it’s actually the environment that’s moving instead of the player. The chunks move using a simple z-axis translation that only runs when the move button is pressed. When the player collider hits a trigger on a chunk, it tells the game to spawn the right chunk at a spawnpoint at the end of the current chunk. Chunks are spawned in an alternating pattern of main, branch, main, and so on. This creates the illusion of choosing a path, going down it for a while, and then coming across another branch.

The hardest part of this system to figure out was how the player was going to go down a branching path. In the end, I had to simplify the branches a lot, and the two choices branch from the main path at 45 degree angles. When the player chooses a path, it rotates the entire chunk to the correct angle. The triggers at the ends of the branch paths also include information on which sound clip should play, so when the main chunk spawns in again, the audio source will play the correct sound. The nice thing about Unity audio sources is that you can set the spatial blend to 3d and it will naturally fade in and out as you get closer and farther away without any extra scripting.

## Problem Solving

The biggest issue I faced was creating tileable ground planes. If they were flat it would be no problem, but I wanted them to feel a little more natural. I played around with several different ways of making tileable planes. Originally, I wanted all of my chunks to be the same 10x10 size. However, I eventually realized that it would be easier to make the branch chunks 20x10 instead, so that each branching path would have a full chunk of space to fill with trees. Having the branch chunk be 10x10 lets the player get too close to the edge of the ground plane.

To actually make the tiling part of the tileable ground plane, I took a subdivided mesh and sculpted a path slightly depressed into the ground and added some height variation everywhere else. I then cut the mesh in half and swapped the order of the halves. All that was left was to blend the new middle seam and I have a tileable main chunk. To create end points on the larger branch chunk, I copied and separated out strips from the ends of the main chunk. I could then sculpt a branching path and blend it into the strips so they would tile with the main chunk.

## Conclusion

I definitely learned a lot while completing this project! As I started with basically zero coding experience, I was definitely worried if I would be able to accomplish what I wanted to do. It was a lot more fun than I anticipated. If I had more time to work on this project, I would like to add more path variation and come up with a better system of handling chunk movement. In addition, I would like to add some more 3d models to make the different path choice look more distinct.
